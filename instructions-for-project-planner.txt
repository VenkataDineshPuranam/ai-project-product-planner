Project Product Management Gantt Master Guide
Cursor AI Master Build Guide
AI Project Management and AI Product Management Planner with Microsoft Project–Style Gantt Scheduling
Use case: Build a production-grade, offline-capable planning application in Cursor AI for managing AI projects and AI products.
Recommended workflow: Use Cursor Plan Mode first. Approve the architecture and data model before allowing Agent to implement.
Target result: A professional project scheduler with WBS, Gantt, dependencies, milestones, resources, baselines, critical path, AI product roadmaps, AI lifecycle gates, evaluation tracking, AI FinOps, governance and executive reporting.
﻿
1. What You Are Building
Create a local-first web application called:
AI Project and Product Management Planner
The application must combine:
Traditional project-management scheduling.
AI product-management planning.
AI/ML/LLM engineering lifecycle management.
Responsible-AI, security and governance controls.
AI FinOps, token economics and operational-readiness tracking.
The application must behave like a professional desktop project-planning tool, with a task grid on the left and a synchronized interactive Gantt chart on the right.
It must run locally on Windows without requiring a cloud account, external API key or backend server after installation/build.
﻿
2. Recommended Technical Architecture
Use:
React
TypeScript
Vite
Local-first persistence using IndexedDB
JSON as the canonical interchange format
CSV import/export
XLSX export through a locally bundled library
SVG or Canvas for the Gantt timeline
A deterministic scheduling engine implemented in TypeScript
Vitest for unit tests
Playwright for end-to-end tests
ESLint and strict TypeScript checks
Do not depend on a hosted API, SaaS service or runtime CDN.
Bundle all runtime assets locally.
Prefer an internal Gantt implementation if third-party licensing, offline use or missing scheduling features create risk. A third-party library may be used only after checking its license, offline compatibility, accessibility, maintenance status and ability to support dependency arrows, baselines, critical path and editable task bars.

7. Task and Scheduling Data Model
Use a task structure comparable to:

type DependencyType = "FS" | "SS" | "FF" | "SF";
type SchedulingMode = "auto" | "manual";
type ConstraintType =
  | "ASAP"
  | "ALAP"
  | "SNET"
  | "SNLT"
  | "FNET"
  | "FNLT"
  | "MSO"
  | "MFO";

interface Task {
  id: string;
  projectId: string;
  parentId: string | null;
  wbsCode: string;
  sequence: number;

  name: string;
  description?: string;
  workstreamId?: string;
  ownerId?: string;

  schedulingMode: SchedulingMode;
  isSummary: boolean;
  isMilestone: boolean;

  start: string;
  finish: string;
  durationMinutes: number;
  workMinutes: number;
  remainingWorkMinutes: number;

  percentComplete: number;
  physicalPercentComplete?: number;

  constraintType: ConstraintType;
  constraintDate?: string;
  deadline?: string;

  calendarId: string;
  priority: number;

  fixedCost: number;
  costAccrual: "start" | "prorated" | "end";

  baselineStart?: string;
  baselineFinish?: string;
  baselineDurationMinutes?: number;
  baselineWorkMinutes?: number;
  baselineCost?: number;

  actualStart?: string;
  actualFinish?: string;
  actualWorkMinutes?: number;
  actualCost?: number;

  totalFloatMinutes?: number;
  freeFloatMinutes?: number;
  isCritical?: boolean;

  status: "not-started" | "in-progress" | "blocked" | "complete" | "cancelled";
  tags: string[];
}

Dependency structure:

interface Dependency {
  id: string;
  predecessorTaskId: string;
  successorTaskId: string;
  type: DependencyType;
  lagMinutes: number;
}

Resource assignment structure:

interface Assignment {
  id: string;
  taskId: string;
  resourceId: string;
  units: number;
  plannedWorkMinutes: number;
  actualWorkMinutes: number;
  remainingWorkMinutes: number;
  costRateId?: string;
}

8. Scheduling Engine Requirements
The scheduling engine must be deterministic and testable independently of the UI.
8.1 Calendar logic

Working-hour intervals.
Weekends.
Holidays.
Project calendars.
Resource calendars.
Task calendars.
Calendar inheritance and override.
Duration addition and subtraction across working time.
Time-zone-safe date handling.
8.2 Dependency logic
Support:
FS: successor starts after predecessor finishes.
SS: successor starts after predecessor starts.
FF: successor finishes after predecessor finishes.
SF: successor finishes after predecessor starts.
Positive lag.
Negative lag or lead.
Dependency-cycle detection.
Clear validation errors for impossible schedules.
8.3 Critical Path Method
Implement:
Topological ordering.
Forward pass.
Early start.
Early finish.
Backward pass.
Late start.
Late finish.
Total float.
Free float.
Critical-path identification.
Multiple critical paths.
Recalculation after edits.
Summary tasks must roll up from child tasks and must not create circular calculation.
8.4 Constraints
Implement and test:
As Soon As Possible.
As Late As Possible.
Start No Earlier Than.
Start No Later Than.
Finish No Earlier Than.
Finish No Later Than.
Must Start On.
Must Finish On.
Deadlines that warn without automatically constraining the task.
8.5 Progress and forecasting
Support:
Status date.
Actual start and finish.
Actual and remaining duration/work.
Rescheduling incomplete work.
Forecast finish.
Schedule variance.
Baseline variance.
Milestone slippage.
Earned-value fields where enabled.
8.6 Resource scheduling
Support:
Capacity by calendar.
Assignment units.
Work calculation.
Resource utilization.

Manual leveling suggestions.

16. Staged Cursor Implementation Prompts
Do not ask Cursor to build the entire product in one agent run.
Prompt 1 — Documentation and architecture

Using the approved plan, create only the PRD, data model, scheduling-engine specification, UX specification, security specification, test strategy and ADRs.

Do not implement UI or production code.

Cross-check every requirement for contradictions, missing entities, untestable acceptance criteria and unsupported assumptions. End with a requirements traceability matrix.

Prompt 2 — Domain model and persistence

Implement the typed domain model, validation schemas, repository interfaces and IndexedDB persistence.

Write unit tests first.

Include schema versioning, safe migrations, import validation, transaction handling and recovery from corrupted local data.

Do not implement the Gantt UI yet.

Prompt 3 — Scheduling engine

Implement the deterministic scheduling engine as a UI-independent TypeScript module.

Write tests before implementation for calendars, all four dependency types, positive and negative lag, constraints, deadlines, cycles, summary roll-up, forward and backward passes, critical path, total float, free float, baselines and progress forecasting.

Use property-based or generated tests for schedule invariants where practical.

Do not proceed until the focused test suite passes.

Prompt 4 — Task grid and Gantt

Implement the synchronized WBS task grid and Gantt timeline against the tested scheduling engine.

Prioritize correctness, keyboard accessibility, virtualization and deterministic rendering.

Add summary bars, milestones, dependency arrows, baselines, critical path, progress overlays, zoom and calendar shading.

Do not add product-management modules yet.

Prompt 5 — Product and AI lifecycle modules

Implement product vision, outcomes, OKRs, personas, opportunities, experiments, roadmap, AI lifecycle, datasets, models, prompts, RAG, agents, evaluations and governance gates.

Link each item to relevant tasks, milestones, releases, owners and evidence.

Add representative unit and integration tests.

Prompt 6 — Resources, cost and AI FinOps

Implement resource assignments, capacity, utilization, over-allocation, rate cards, planned/actual/forecast cost and AI FinOps.

Support token, request, inference, evaluation, observability and human-review costs.

Calculate cost per accepted outcome and quality-versus-cost views.

Do not optimize cost by weakening validation.

Prompt 7 — Import, export and reports

Implement versioned JSON import/export, validated CSV import/export, locally bundled XLSX export, backup/restore and print-friendly reports.

Reject invalid or dangerous content with clear row-level errors.

Never execute imported content as code or markup.

Prompt 8 — Sample data

Create the enterprise RAG program sample with at least 120 internally consistent tasks.

Validate WBS hierarchy, dependency graph, calendar calculations, resources, costs, baselines, critical path, risks, governance gates and evaluation data.

Add an automated sample-data integrity test.

18. Performance Budgets
Use explicit performance targets.
Initial targets:
First meaningful screen within 2 seconds on a normal modern laptop after local build.
Smooth scrolling for 2,000 tasks.
Schedule recalculation under 250 milliseconds for a typical 500-task project.
Schedule recalculation under 1 second for 2,000 tasks, unless profiling proves a justified exception.
Local save feedback within 300 milliseconds.
No quadratic algorithm on common task-edit paths unless documented and bounded.
Lazy-load non-critical reports.
Virtualize long task and resource lists.
Measure before claiming the targets have been achieved.

Create the empty repository.

Answer Cursor's material clarification questions.
Review and edit the generated plan.
Save the plan in the repository.

22. Practical Advice
The most common failure is asking Cursor:
“Build me a Microsoft Project clone for AI projects.”
That request is too broad. It encourages a visually attractive but logically weak chart.
The correct order is:

Requirements
    ↓
Domain model
    ↓
Scheduling specification
    ↓
Scheduling tests
    ↓
Scheduling engine
    ↓
Persistence
    ↓
WBS grid
    ↓
Gantt rendering
    ↓
AI product modules
    ↓
FinOps and governance
    ↓
Import/export
    ↓
End-to-end validation

The scheduling engine is the core product. A Gantt bar without validated calendar, dependency, constraint, baseline and critical-path logic is only a drawing, not a project-management system.
